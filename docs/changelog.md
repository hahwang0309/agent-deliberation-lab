# 변경 이력

## 토론 메커니즘 재설계 (2026-10)
각자 자기 말만 하던 순차 발언 생성을, 상태를 보고 상호작용하는 토론으로 바꿨습니다. 이론과 규칙은 [architecture.md](architecture.md#토론-메커니즘)를 참고하세요.
- **진행 계획:** 명제 수와 명제별 발언 예산을 참가자 수와 발언 수로 계산합니다. 명제마다 전원이 먼저 입장을 밝히고, 마지막에 종결 라운드(최종 입장과 바뀐 점)를 둡니다. 키워드 기반 소주제 전환과 모더레이터의 주기적 질문은 없앴습니다.
- **발화 행위:** 무작위 선택을 상태 기반 규칙으로 바꿨습니다. 행위 종류는 입장 표명, 동조·확장, 사례 추가, 반박, 근거 반박, 반박에 답변, 중재, 제3안, 반대 검토, 최종 입장입니다. 반박·질문을 받은 참가자는 응답할 의무가 생기고, 교착되면 제3자가 중재합니다. 2명 토론에서는 모더레이터가 지목 질문을 합니다.
- **발언 분석:** 발언마다 LLM을 1회 더 호출해 주장, 공격·지지 대상, 입장, 설득력을 분석합니다. 결과는 메시지 `meta`와 SSE `analysis` 이벤트로 나갑니다.
- **입장 동역학:** Friedkin–Johnsen + 제한 신뢰 모델로 명제별 입장(−1~+1)을 갱신하고, 그 입장을 발언 프롬프트에 넣습니다. 영어 키워드로 신념을 바꾸던 `EvolvingPersona`(`src/models/persona_evolution.py`)는 삭제했습니다.
- **상대 발언 전달:** 최근 8개 발언을 각 1200자까지, 대상 발언은 전문을 넣습니다. 이전에는 200자로 잘랐습니다.
- **보고서·화면:** 보고서에 "토론 과정의 입장 변화"(명제별 궤적, 영향, 답하지 않은 반박)를 추가했습니다. 토론 화면에는 현재 입장 패널을 넣고 새 발화 행위 라벨을 달았습니다.
- **사람 응답의 예산 처리:** 사람 발언에 대한 응답이 명제 예산을 씁니다. 예산이 끝났으면 추가 발언으로 수행합니다.
- **재개:** 상태 스냅숏으로 복원합니다. 스냅숏이 없는 이전 토론은 발언 수로 위치를 계산합니다.
- **비용:** 실측(N=3, S=9, Haiku 4.5) 결과 LLM 호출이 12회에서 21회로, 입력 토큰이 약 2.8배로 늘었습니다.
- **설정 정리:** 쓰이지 않게 된 설정 16개를 `discussion_config.py`에서 삭제했습니다(진화 가중치, 모더레이터 분석 창, `prefer_building_over_challenging` 등).

## 토론 품질 개선 (2026-10)
실제 토론("GAI는 인류의 구원자인가 아니면 적인가?") 점검에서 나온 문제를 고쳤습니다.
- 사실 지어내기 방지: 에이전트 프롬프트에 출처 없는 수치·고유명사·개인 경험 금지와 추정 표시 규칙을 넣었습니다. 모더레이터는 더 이상 "수치·출처를 대라"고 묻지 않습니다. 보고서는 출처 없는 수치·사례에 기댄 입장에 `unsourced_specifics` 표시를 하고, 요약에서는 이를 사실이 아닌 주장으로 다룹니다.
- 소주제는 구조화 출력으로 생성합니다(텍스트 목록 파싱 제거). 찬반 양쪽을 모두 다루도록 지시했고, 발언 예산을 소주제 수로 나눠 차례로 전환해 모든 관점을 다룹니다.
- 모더레이터는 AI 발언 3개마다(`moderator_every_statements`), 또는 소주제 전환·추상적 발언이 이어질 때만 개입합니다. 무작위 개입을 없앴고, 이전 질문은 반복하지 않으며, 마지막 발언 뒤에는 개입하지 않습니다. 질문만 짧게, 마크다운 없이 냅니다.
- 맞장구 억제(동의로 시작하지 않기, 자기 입장 유지, `prefer_building_over_challenging` 0.6 → 0.5). 후반부에도 발언이 가장 적은 참가자를 우선합니다.
- 보고서 요약은 쟁점 분류에 없는 입장을 참가자에게 붙이지 않습니다.
- `TAVILY_API_KEY`가 없으면 웹 검색 옵션을 422(`WEB_SEARCH_UNAVAILABLE`)로 거부합니다.
- 화면에서 굵게·제목·구분선을 렌더링하고, 참가자 이름은 적힌 그대로 부르도록 했습니다.

## 합의 점수 4종 (2026-10)
- 종합 / AI간 / 인간간 / AI-인간간 점수를 표시합니다. 인간간은 사람이 2명 이상일 때, AI-인간간은 사람이 참여했을 때만 계산합니다.
- 계산 방식을 "지지·반대 중 큰 쪽 비율"에서 "참가자 쌍별 일치도"(찬성 1, 부분찬성 0.7, 반대 0, 일치도 1 − |차이|)로 바꿨습니다. 네 점수를 같은 척도로 비교할 수 있게 하기 위해서입니다. 이 방식은 더 엄격해서, 2:1로 갈린 쟁점이 67%(부분 합의)에서 33%(이견)로 바뀝니다.
- `discussion_reports.ai_human_score` 컬럼을 추가했습니다. 기존 보고서의 점수는 재생성해야 새 방식으로 바뀝니다.

## 범용 페르소나 토론 플랫폼으로 재설계 (2026-10)

"행정조사 중복 분석" 전용 시스템을 범용 토론 플랫폼으로 다시 만들었습니다. 사람이 토론에 끼어들 수 있고, 끝나면 종합보고서가 만들어지며, 계정은 관리자가 승인하거나 발급합니다.

### Phase 5: 재개·문서·정리
- 서버 재시작으로 중단된(`interrupted`) 토론을 저장된 발언에서 이어 진행(`POST /discussions/{id}/resume`). seq·발언 예산·소주제를 유지하고, 응답받지 못한 사람 발언에는 먼저 응답합니다.
- 문서를 README + `docs/` 8개로 다시 썼고, 예전 행정조사 문서를 정리했습니다.
- 쓰지 않는 의존성(`rich`)을 제거했습니다.

### Phase 4: 사람 개입
- AI 발언 중 발언 요청 → 그 발언이 끝나면 토론이 `awaiting_human`으로 멈추고 무기한 대기 → 제출, 포기, 생성자·관리자의 회수, 중지 중 하나로 종료.
- 다음 AI 발언이 사람 발언에 응답합니다(`respond_to_human`, `in_reply_to_seq`). 이 응답은 발언 예산을 넘어도 수행됩니다.
- 여러 사람이 차례로 발언할 수 있는 대기열, 1인당 발언 횟수·글자 수 제한, 사람의 입장을 보고서에 반영.
- 수정: 발언권을 주기 전에 상태를 기록하도록 바꿔 경쟁 조건을 없앴습니다.

### Phase 3: 계정·관리자·비용 제한
- Basic 인증을 없애고 httpOnly 쿠키 JWT + CSRF 방어로 바꿨습니다(PyJWT, bcrypt). 기존 passlib와 bcrypt 5의 비호환 문제도 해결했습니다.
- 가입 신청 → 관리자 승인, 또는 관리자 발급(임시 비밀번호, 첫 로그인 시 변경). 정지·비밀번호 변경 시 세션이 즉시 무효가 됩니다.
- 조회는 모든 사용자(공동 참여), 조작은 생성자·관리자만. 사용자별 동시 실행·일일 시작 수 제한, 비싼 기능은 관리자만.
- 수정: 로그인 후 이동 주소의 오픈 리다이렉트, 예약 도메인 이메일로 만든 관리자가 로그인하지 못하던 문제.

### Phase 2: 종합보고서
- 쟁점·입장을 추출하고(검증과 재시도 포함), 합의 점수를 코드로 계산하고(종합·AI·사람), 요약·열린 질문·제언을 작성합니다. Markdown/JSON으로 내려받을 수 있습니다.
- 점수 공식 수정: 부분 찬성이 반대 쪽 점수에도 더해져 `[반대, 부분찬성]`이 75%로 나오던 문제를 고쳤습니다. 입장이 2개 미만인 쟁점은 "판단 보류"로 둡니다.

### 기본 모델
- 기본 provider를 Claude로, 기본 모델을 `claude-haiku-4-5-20251001`로 바꿨습니다.
- 수정: 응답 토큰 500 한도에서 페르소나 JSON과 한국어 발언이 잘리던 문제, 목록 필드를 문자열로 주는 출력 형식 처리.

### Phase 1: 엔진·런타임 재구축
- 토론을 이벤트 루프 안의 비동기 작업으로 실행합니다. 완성된 발언은 저장한 뒤 발행하고(seq), SSE로 놓친 발언부터 다시 받을 수 있습니다.
- 프롬프트를 모두 YAML로 옮겼고, 참가자별로 provider와 모델을 지정할 수 있습니다.
- 행정조사·일괄 분석 기능을 삭제했습니다. 해당 데이터는 마이그레이션할 때 `data/legacy_export/`로 내보냅니다.

### Phase 0: 기반
- Alembic 마이그레이션 도입, lifespan, stdout 로깅, LLM 타임아웃·재시도, Docker 정리(`.env`를 이미지에 넣지 않음), 미사용 의존성 제거.

## 이전 이력: 행정조사 중복 판별 시스템 v2.0

예전 `CHANGELOG_v2.md`의 요지입니다. 일관성 지침 통합, RAG 웹 검색(검색 필요성 판단), 페르소나 자동 생성과 루브릭 평가를 갖춘 행정조사 중복 판별 기능이었습니다. 이 기능은 이번 재설계에서 삭제되었습니다.
