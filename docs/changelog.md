# 변경 이력

## 범용 페르소나 토론 플랫폼으로 재설계 (2026-10)

"행정조사 중복 분석" 전용 시스템을 범용 토론 플랫폼으로 다시 만들었습니다. 사람이 토론에 끼어들 수 있고, 끝나면 종합보고서가 만들어지며, 계정은 관리자가 승인하거나 발급합니다.

### Phase 5: 재개·문서·정리
- 서버 재시작으로 중단된(`interrupted`) 토론을 저장된 발언에서 이어 진행(`POST /discussions/{id}/resume`). seq·발언 예산·소주제를 유지하고, 응답받지 못한 사람 발언에는 먼저 응답합니다.
- 문서를 README + `docs/` 8개로 다시 썼고, 예전 행정조사 문서를 정리했습니다.
- 쓰지 않는 의존성(`rich`)을 제거했습니다.

### Phase 4: 사람 개입
- AI 발언 중 발언 요청 → 그 발언이 끝나면 토론이 `awaiting_human`으로 멈추고 무기한 대기 → 제출, 포기, 생성자·관리자의 회수, 중지 중 하나로 종료.
- 다음 AI 발언이 사람 발언에 응답합니다(`respond_to_human`, `in_reply_to_seq`). 이 응답은 발언 예산을 넘어도 수행됩니다.
- 여러 사람이 차례로 발언할 수 있는 대기열, 1인당 발언 횟수·글자 수 제한, 사람의 입장을 보고서에 반영.
- 수정: 발언권을 주기 전에 상태를 기록하도록 바꿔 경쟁 조건을 없앴습니다.

### Phase 3: 계정·관리자·비용 제한
- Basic 인증을 없애고 httpOnly 쿠키 JWT + CSRF 방어로 바꿨습니다(PyJWT, bcrypt). 기존 passlib와 bcrypt 5의 비호환 문제도 해결했습니다.
- 가입 신청 → 관리자 승인, 또는 관리자 발급(임시 비밀번호, 첫 로그인 시 변경). 정지·비밀번호 변경 시 세션이 즉시 무효가 됩니다.
- 조회는 모든 사용자(공동 참여), 조작은 생성자·관리자만. 사용자별 동시 실행·일일 시작 수 제한, 비싼 기능은 관리자만.
- 수정: 로그인 후 이동 주소의 오픈 리다이렉트, 예약 도메인 이메일로 만든 관리자가 로그인하지 못하던 문제.

### Phase 2: 종합보고서
- 쟁점·입장을 추출하고(검증과 재시도 포함), 합의 점수를 코드로 계산하고(종합·AI·사람), 요약·열린 질문·제언을 작성합니다. Markdown/JSON으로 내려받을 수 있습니다.
- 점수 공식 수정: 부분 찬성이 반대 쪽 점수에도 더해져 `[반대, 부분찬성]`이 75%로 나오던 문제를 고쳤습니다. 입장이 2개 미만인 쟁점은 "판단 보류"로 둡니다.

### 기본 모델
- 기본 provider를 Claude로, 기본 모델을 `claude-haiku-4-5-20251001`로 바꿨습니다.
- 수정: 응답 토큰 500 한도에서 페르소나 JSON과 한국어 발언이 잘리던 문제, 목록 필드를 문자열로 주는 출력 형식 처리.

### Phase 1: 엔진·런타임 재구축
- 토론을 이벤트 루프 안의 비동기 작업으로 실행합니다. 완성된 발언은 저장한 뒤 발행하고(seq), SSE로 놓친 발언부터 다시 받을 수 있습니다.
- 프롬프트를 모두 YAML로 옮겼고, 참가자별로 provider와 모델을 지정할 수 있습니다.
- 행정조사·일괄 분석 기능을 삭제했습니다. 해당 데이터는 마이그레이션할 때 `data/legacy_export/`로 내보냅니다.

### Phase 0: 기반
- Alembic 마이그레이션 도입, lifespan, stdout 로깅, LLM 타임아웃·재시도, Docker 정리(`.env`를 이미지에 넣지 않음), 미사용 의존성 제거.

## 이전 이력: 행정조사 중복 판별 시스템 v2.0

예전 `CHANGELOG_v2.md`의 요지입니다. 일관성 지침 통합, RAG 웹 검색(검색 필요성 판단), 페르소나 자동 생성과 루브릭 평가를 갖춘 행정조사 중복 판별 기능이었습니다. 이 기능은 이번 재설계에서 삭제되었습니다.
