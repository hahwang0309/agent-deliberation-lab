# 행정조사 중복 판별 AI 토론 시스템 설계

## 📋 프로젝트 개요

행정조사 중복 여부를 AI 에이전트 토론을 통해 판별하는 시스템

### 핵심 목표
- 두 개의 행정조사(A, B)가 중복인지 **공식 기준**에 따라 자동으로 판별
- 다양한 관점의 AI 페르소나가 토론을 통해 종합적으로 분석
- 모더레이터가 토론을 중재하고 적정 라운드 수 결정
- 토론 결과를 구조화된 보고서로 생성
- 루브릭 기반 평가로 신뢰도 제공

### 📚 관련 문서
- **[중복 판별 기준](DUPLICATION_CRITERIA.md)**: 공식 판별 기준 및 유형 분류
- **[시스템 아키텍처](ARCHITECTURE.md)**: 전체 시스템 구조
- **[API 문서](../api/README.md)**: API 엔드포인트 및 사용법

### 2. 페르소나 동적 생성 시스템

**📌 핵심 개념: AI가 조사 내용을 분석하여 최적의 페르소나를 자동 생성**

#### 2.1 페르소나 생성 프로세스

```
[1단계] 조사 분석
├─ 행정조사 A, B의 특성 파악
├─ 주요 쟁점 식별 (법적, 절차적, 기술적, 정책적 등)
└─ 필요한 전문 분야 도출

[2단계] 페르소나 설계
├─ LLM이 3~5개의 적합한 페르소나 역할 생성
├─ 각 페르소나의 전문성, 관점, 성향 정의
└─ 페르소나 간 다양성 보장 (다각도 분석)

[3단계] 페르소나 구체화
├─ 이름, 직책, 배경 설정
├─ 분석 관점 및 우선순위 정의
└─ 토론 스타일 및 커뮤니케이션 방식 설정
```

#### 2.2 페르소나 생성 가이드라인

**필수 다양성 확보:**
- 최소 3가지 이상의 상이한 관점 포함
- 찬성/반대/중립 의견 분포 고려
- 전문성 레벨 다양화 (이론가, 실무자, 경험자 등)

**조사 특성별 페르소나 예시:**

| 조사 유형 | 자동 생성될 수 있는 페르소나 예시 |
|-----------|----------------------------------|
| **법령/규제 관련** | 헌법학자, 행정법 전문가, 규제영향분석가, 입법정책관 |
| **기술/통계 조사** | 데이터과학자, 통계학자, IT보안전문가, 정보시스템감리사 |
| **민원/서비스** | 공공서비스디자이너, 민원분석가, 행정사, 시민옴부즈맨 |
| **환경/안전** | 환경공학자, 안전관리전문가, 보건의료인, 주민대표 |
| **경제/산업** | 경제학자, 산업분석가, 세무사, 기업경영인 |
| **교육/복지** | 교육정책전문가, 사회복지사, 학부모대표, NGO활동가 |

#### 2.3 페르소나 자동 생성 프롬프트 구조

```python
PERSONA_GENERATION_PROMPT = """
행정조사 A와 B의 중복 여부를 판별하기 위해 최적의 전문가 페르소나를 생성해주세요.

<조사 A 정보>
{investigation_a_summary}

<조사 B 정보>
{investigation_b_summary}

다음 기준으로 3~5개의 페르소나를 생성하세요:

1. 조사의 핵심 특성(법적, 기술적, 정책적 등)을 고려한 전문 분야
2. 다양한 관점 확보 (예: 이론가, 실무자, 수혜자/피해자 등)
3. 중복 판별에 실질적 기여 가능한 역할

각 페르소나는 다음 정보를 포함:
- role: 역할/직책
- name: 이름
- expertise: 전문 분야 (상세)
- perspective: 분석 관점 (어떤 기준으로 판단하는가)
- style: 토론 스타일 (분석적, 비판적, 조정적 등)
- background: 배경 (경력, 경험)
- key_concerns: 주요 관심사 (중복 판별 시 중점을 둘 부분)
"""
```

#### 2.4 페르소나 품질 보장

**자동 검증 체크리스트:**
- [ ] 3개 이상의 서로 다른 전문 분야 포함
- [ ] 찬성/반대/중립 관점 균형
- [ ] 실무적/이론적/제도적 관점 포함
- [ ] 각 페르소나의 역할이 명확히 구분됨
- [ ] 조사 특성과 연관성 높음

**재생성 조건:**
- 페르소나 간 역할 중복도 > 70%
- 필수 관점(법적, 실무적) 누락
- 전문성 레벨 편중 (모두 이론가 또는 모두 실무자)

#### 2.5 기본 페르소나 풀 (참고용)

**법적/제도적 관점:**
- 행정법 전문가, 헌법학자, 입법조사관, 행정심판관, 감사원 조사관

**실무/운영 관점:**
- 행정공무원, 지방자치단체 담당자, 민원처리담당, 정책실무자

**기술/분석 관점:**
- 데이터분석가, 통계학자, 정보시스템전문가, 평가전문가

**정책/전략 관점:**
- 정책연구원, 행정학자, 공공관리전문가, 컨설턴트

**이해관계자 관점:**
- 시민대표, 사업자대표, NGO활동가, 전문가협회, 학계

**기타 필요시:**
- 언론인(투명성), 예산전문가(비용), 국제비교전문가(벤치마킹) 등

> 💡 **핵심**: LLM이 매번 조사 내용을 분석하여 최적의 조합을 선택하고,
> 필요시 새로운 역할을 창의적으로 생성할 수 있도록 설계

### 3. 모더레이터 시스템
**역할:**
- 토론 진행 및 중재
- 라운드 종료 조건 판단
- 합의 도달 여부 평가
- 논의 방향 조정

**라운드 제어:**
- 최소: 3라운드 (기본 분석 보장)
- 최대: 10라운드
- 조기 종료 조건:
  - 모든 페르소나가 명확한 입장 표명
  - 합의 또는 명확한 의견 분립 확인
  - 더 이상 새로운 논점 없음

### 4. 토론 프로세스

```
[라운드 1-2] 초기 분석
├─ 각 페르소나: 담당 관점에서 행정조사 A, B 분석
├─ 유사점과 차이점 식별
└─ 초기 의견 제시

[라운드 3-6] 심화 토론
├─ 모더레이터: 쟁점 정리 및 토론 유도
├─ 페르소나: 교차 검토 및 반론
├─ 중복 여부에 대한 논거 강화
└─ 부분적 중복 가능성 검토

[라운드 7-10] 합의 도출
├─ 모더레이터: 종합 의견 요청
├─ 페르소나: 최종 입장 정리
├─ 중복 정도 및 근거 명확화
└─ 권고사항 제시
```

### 5. 보고서 생성

**보고서 구조:**
```
1. 요약 (Executive Summary)
   - 판별 결과 (중복/비중복/부분중복)
   - 신뢰도 점수
   - 핵심 근거 3가지

2. 조사 개요
   - 행정조사 A 정보
   - 행정조사 B 정보
   - 비교 분석 항목

3. 토론 분석
   - 페르소나별 의견 요약
   - 주요 쟁점 정리
   - 합의/불합의 사항

4. 중복성 평가
   - 목적 유사도
   - 대상 중복도
   - 항목 중복도
   - 시기 중복도
   - 종합 평가

5. 권고사항
   - 통합 가능성
   - 조정 필요사항
   - 실행 방안

6. 부록
   - 전체 토론 내용
   - 페르소나 상세 정보
```

### 6. 루브릭 평가 시스템

**평가 기준 (5개 영역, 각 5점 만점):**

| 영역 | 평가 항목 | 배점 |
|------|----------|------|
| **분석 깊이** | 다각도 분석 수행 여부 | 5점 |
| **논거 품질** | 논리적 근거와 증거 제시 | 5점 |
| **합의 수준** | 페르소나 간 합의 정도 | 5점 |
| **실용성** | 실무 적용 가능성 | 5점 |
| **완성도** | 보고서 완성도 및 명확성 | 5점 |

**신뢰도 등급:**
- 25점: 매우 높음 (Excellent)
- 20-24점: 높음 (Good)
- 15-19점: 보통 (Fair)
- 10-14점: 낮음 (Poor)
- 10점 미만: 매우 낮음 (Insufficient)

## 📊 데이터 모델

### InvestigationInput
```python
class InvestigationData(BaseModel):
    name: str
    purpose: str
    scope: str
    target: str
    methods: str
    period: str
    legal_basis: str
    department: str
    additional_info: Optional[str] = None

class InvestigationAnalysisRequest(BaseModel):
    topic: str = "행정조사 중복조사 판별"
    investigation_a: InvestigationData
    investigation_b: InvestigationData
    max_rounds: int = 10
    min_rounds: int = 3
```

### AnalysisResult
```python
class DuplicationAssessment(BaseModel):
    result: Literal["중복", "비중복", "부분중복"]
    confidence_score: float  # 0.0 ~ 1.0
    key_reasons: List[str]
    
class SimilarityScores(BaseModel):
    purpose_similarity: float
    target_overlap: float
    method_similarity: float
    timing_overlap: float
    overall_score: float

class InvestigationAnalysisResult(BaseModel):
    discussion_id: str
    assessment: DuplicationAssessment
    similarity_scores: SimilarityScores
    report: str  # Markdown format
    rubric_scores: Dict[str, float]
    total_score: float
    confidence_level: str
    recommendations: List[str]
    discussion_summary: str
    generated_at: datetime
```
